# 多 Agent 协作的基本模式
标题: 多 Agent 协作的基本模式
来源: 本地演示知识库 / 公开资料整理

多 Agent 协作不是把一个简单任务机械地拆给多个模型，而是把不同职责、不同上下文和不同质量约束显式分配给多个角色。常见的稳定模式是 Planner–Executor–Reviewer：Planner 负责目标分解、依赖识别和任务排序；Executor 负责使用工具或知识库完成单个子任务；Reviewer 负责检查完整性、一致性和引用真实性，并决定重试或降级。

一个有效的研究型 Agent 系统通常需要把任务表示为有向无环图（DAG）。DAG 中的节点是子任务，边表示依赖关系。没有依赖的任务可以放在同一拓扑层并行执行，依赖任务必须等待上游完成。这样可以同时获得并行效率与结果一致性。

多 Agent 的主要收益来自职责分离和质量闭环：规划不再混入执行，执行结果能够被独立审核，审核反馈还能进入下一轮重试。但它也带来新的成本，包括模型调用次数增加、上下文膨胀、错误传播、状态一致性和可观测性变差。因此生产系统必须控制并行度、设置重试上限，并记录每个任务的状态、耗时、引用和失败原因。
