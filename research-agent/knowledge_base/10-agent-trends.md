# 多 Agent 与上下文工程趋势
标题: 多 Agent 与上下文工程趋势
来源: 本地演示知识库 / 公开资料整理

当前 Agent 工程正从“让单次对话更聪明”转向“让任务流程更可靠”。重点包括显式状态、工具调用、任务分解、可恢复执行、记忆检索、证据引用和自动评估。多 Agent 并非天然优于单 Agent；当任务边界清晰、工具稳定时，一个 Agent 加工作流可能更便宜。多 Agent 更适合职责冲突明显、需要独立审核或可以并行的任务。

上下文工程强调在正确时间给模型正确的信息。长上下文并不等于有效上下文，冗余历史会增加噪声和成本。摘要、结构化状态和向量记忆是三种常用压缩方式，分别适合保留结论、控制流程和找回历史证据。

未来系统更可能采用可插拔模型和工具、细粒度评估与人工复核结合的形态。作品项目应展示可验证的工程取舍：为什么拆 Agent、为什么需要记忆、RAG 指标如何测量、失败后如何降级。清晰的数字和边界比堆叠框架名称更有说服力。
