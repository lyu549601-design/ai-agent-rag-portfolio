# LangGraph 编排与状态管理
标题: LangGraph 编排与状态管理
来源: 本地演示知识库 / 公开资料整理

LangGraph 使用状态图描述 Agent 工作流。节点接收共享状态并返回状态增量，边决定节点之间的流转。对于研究助手，可以把 Planner、Executor、Reviewer 和报告汇总分别实现为节点，并在审核节点后根据审核结果回到执行节点或进入结束节点。

状态应保存业务上真正需要跨步骤复用的内容，例如研究主题、任务列表、依赖状态、子任务结果、引用、重试次数和错误。原始会话和历史工具输出不宜全部塞入状态，否则上下文会快速膨胀，也会让模型更难识别当前任务所需证据。

同层并行可以用线程池或异步任务实现。并行执行必须遵守三个边界：每个子任务只能读取已完成的依赖结果；共享数据库连接不能跨线程随意复用；任一子任务失败不能无声吞掉，必须进入状态并交给 Reviewer 决定重试或降级。

LangGraph 的价值不在于替代所有 Python 控制流，而在于把可恢复、可分支、可审计的 Agent 流程显式化。演示项目应优先保证流程能跑通、状态可检查、失败可解释，再逐步增加持久化检查和复杂路由。
