# Agent 系统的生产可靠性
标题: Agent 系统的生产可靠性
来源: 本地演示知识库 / 公开资料整理

多 Agent 研究系统在生产环境中最常见的风险不是“模型不够聪明”，而是超时、重复调用、状态丢失、上下文膨胀和失败不可见。每个子任务都应有超时、重试上限和终态；每个有副作用的工具都需要幂等键；整条流程需要任务级状态和可恢复点。

成本与延迟可以通过并行同层任务、限制检索条数、缓存嵌入和摘要、复用已审核证据来控制。但缓存必须带版本和权限键，知识库或提示词变化后不能继续使用不兼容的旧结果。并发并非越高越好，外部模型限流、数据库连接和费用都会成为瓶颈。

可观测性至少包括结构化日志、任务耗时、模型调用次数、检索命中、重试原因和最终状态。对于求职作品，不必引入完整监控平台，但应保存 JSON 结果和可复现实验脚本，让面试官能看到系统为什么成功、在哪里失败以及如何改进。
